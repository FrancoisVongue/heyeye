# EYE — фовеальное зрение для агента. Архитектурный план

> Живой документ. Описывает систему так, как она выглядит ГОТОВОЙ.
> Отклонения по ходу разработки фиксируются в «Журнале отклонений» внизу с причиной.

## Принципы (философия, из которой всё следует)

1. **Периферия — это почти ничего.** «Тут квадратик, тут скорее всего текст, тут цветное пятно». 3-5 символов смысла на регион, не содержимое.
2. **Стримим смыслы, не пиксели.** Модель получает компактный эскиз и САМА решает, куда сфокусироваться. Никакой отдельной «политики взгляда» — фокус это обычный tool-call рассуждающей модели.
3. **Читаем слева-направо, сверху-вниз.** Регионы в эскизе отсортированы в порядке чтения.
4. **Изменения, а не кадры.** watch() отдаёт диффы («справа появился новый квадрат»), не переснимает всё.
5. **Интерактив не растворяется.** Кнопка внутри текста не исчезает из эскиза молча — периферия человека тоже цепляется за выделяющееся.
6. **Формат эскиза — контракт.** Мозгу всё равно, откуда эскиз: из CDP (v1, браузер) или из пиксельного детектора (v2, любой экран). Retina — сменный модуль, остальное неизменно.

## Архитектура

```
 Мозг (Claude / любой MCP-клиент)
   │  tools: glance() / focus(id) / watch()
   ▼
 mcp-server.js  ── обвязка, ничего не решает
   ▼
 ЯДРО
   glance:  retina ──▶ compressor ──▶ sketch      (эскиз ~300-500 ток.)
   focus:   retina(region) ──▶ детали региона     (~500-800 ток.)
   watch:   watcher(диффы регионов) ──▶ события   (~30-50 ток./событие)
   ▼
 РЕТИНА (сменная)
   v1: retina-cdp.js    — CDP DOMSnapshot, ноль ML
   v2: retina-pixels    — захват экрана → Python-сайдкар (OmniParser/OCR) → тот же формат PaintNode
   ▼
 Chrome Canary, ws://127.0.0.1:9222 (тот же тумблер remote debugging, что и сейчас)
```

## Файлы

```
eye/
  PLAN.md            этот документ
  ROADMAP.md         порядок работ, статусы
  src/
    retina-cdp.js    съём: CDP → PaintNode[]         (глубина: парсинг DOMSnapshot)
    compressor.js    PaintNode[] → Region[]           (★ вся «математика» здесь)
    sketch.js        Region[] → текст эскиза          (тупое форматирование)
    focus.js         region id → детали               (средняя сложность)
    watcher.js       мутации → диффы регионов         (★ вторая умная часть)
    mcp-server.js    3 тула через @modelcontextprotocol/sdk (обвязка)
    cli.js           ручной прогон без MCP: stats/dump/glance/focus
```

Где «глубокая» логика, а где клей:
- ★ **compressor.js** — фильтр, квантование, union-find, схлопывание повторов, оверлеи. Единственное место с настоящими алгоритмами и порогами, которые надо крутить.
- ★ **watcher.js** — матчинг регионов между кадрами (что «тот же», что «новый»), шумодав.
- retina-cdp — муторный, но механический парсинг формата DOMSnapshot.
- sketch/focus/mcp-server/cli — клей.

## Форматы данных (контракты)

### PaintNode — выход ретины (любой: CDP или пиксельной)
```json
{
  "type": "text|media|input|action|surface|frame",
  "box": [x, y, w, h],          // абс. координаты документа, CSS px
  "onScreen": true,
  "textLen": 143,               // только длина, НЕ текст
  "fg": "#202124", "bg": "rgba(...)",
  "fontSize": 14, "bold": false,
  "clickable": true,            // сам или через предка (<a>, isClickable)
  "backendId": 4482,            // ручка для focus()/клика (в v2 — id бокса детектора)
  "pos": "fixed", "z": 100,     // для детекта оверлеев
  "paint": 812                  // paint order
}
```

### Region — выход компрессора
```json
{
  "id": 3,
  "kind": "TEXT|LIST|MEDIA|INPUT|ACTION|SURFACE|BAR|OVERLAY|FRAME",
  "cells": [c0, r0, c1, r1],    // сетка, не пиксели
  "color": "dark-on-light|light-on-dark|accent|muted",
  "scale": { "textLen": 1200, "items": 20 },
  "interactive": { "actions": 2, "inputs": 0 },
  "occluded": false,            // накрыт оверлеем
  "pattern": "IMAGE + заголовок-ссылка + ~150 симв",  // для LIST
  "nodeRefs": [4482, 4511]      // топ backendId для focus()
}
```

### Эскиз (то, что читает модель) — целевой вид
```
viewport 1500×950, сетка 12×8, скролл 0%, ниже ещё ~5 экранов (в основном [3])
[1] BAR    (0-11, 0)   светлая: MEDIA-лого(0), INPUT(3-7), ACTION(8), 2 ACTION(10-11)
[2] PANEL  (0-1, 1-7)  тёмная, LIST ×12 мелких [иконка + подпись], кликабельные
[3] LIST   (2-11, 1-7) ×9 крупных карточек [MEDIA слева + заголовок-ссылка + ~150 симв]
```
Бюджет: ≤30 регионов, типично ~350 токенов, максимум 600.

### Ответ focus(id)
```json
{
  "id": 3, "kind": "LIST",
  "items": [ { "title": "Funniest Animal Videos...", "sub": "Daily Dose...", "actions": [{"label":"открыть","backendId":4482,"box":[...]}] } ],
  "text": "полный текст, если TEXT-регион",
  "crop": "опц. путь к кроп-скриншоту только этого бокса"
}
```
Бюджет: ~500-800 токенов. Возвращает точные координаты/ручки — кликать можно существующими инструментами.

### Событие watch()
```
~14:32:05 [3] LIST: +2 элемента сверху
~14:32:11 NEW [7] OVERLAY (2-9, 1-6) тёмная, TEXT ~200 симв + 2 ACTION   ← регионы 2,3 occluded
```

## Алгоритмы

### Compressor (сердце)
```
вход: PaintNode[] (onScreen), viewport
1. ФОН: нода с площадью ≥90% вьюпорта → фон, выкинуть (но запомнить цвет страницы)
2. КВАНТОВАНИЕ: сетка 12×8 (клетка ≈125×119px).
   bbox → диапазон клеток; клетка засчитывается при перекрытии ≥30%,
   мелким — минимум клетка центра. (Дребезг краёв гасится порогом.)
3. СКЛЕЙКА: union-find. Ребро между нодами: одинаковый kind + клетки
   совпадают/смежны (4-связность). Текст сливается с текстом, media с media.
4. ПОВТОРЫ: дети одного родителя, один kind, клеточный размер ±1 клетка,
   count ≥4 → LIST ×N + pattern (описание одного элемента).
5. ИНТЕРАКТИВ: action/input ноды НЕ растворяются: либо свой регион, либо
   регион получает interactive.actions++ (и упоминание в эскизе).
6. СПЕЦФОРМЫ:
   BAR     = регион шириной ≥10 колонок, высотой ≤1 ряд, у верха/низа
   OVERLAY = pos fixed/sticky + z ≥ 100 + площадь ≥30% вьюпорта
             → регионы под ним occluded=true
7. ПОРЯДОК ЧТЕНИЯ: сортировка (r0, c0).
8. ЗА ЭКРАНОМ: contentH/viewportH → «ниже ещё ~N экранов», доминирующий kind
   офскрин-нод → «в основном LIST».
```
Пороги (крутятся глазами на этапе 2): CELL_CLAIM=0.3, GRID=12×8, REPEAT_MIN=4, OVERLAY_Z=100.

### Watcher (диффы)
```
1. Инъекция MutationObserver ИЛИ подписка на CDP DOM.* события → «что-то шевельнулось»
2. Дебаунс 300мс → пере-glance (дёшево: один снапшот)
3. Матчинг старых и новых регионов: тот же kind + пересечение клеток ≥50% → «тот же»
   изменение scale >30% → событие «вырос/усох»; иначе молчание
4. Сетка = шумодав: анимации на ±5px не меняют клетки → событий нет
```

## Ограничения v1 (осознанные)
- Только главный фрейм. Кросс-доменные iframe → регион `FRAME` без содержимого (заглядывание — в focus() позже).
- Canvas/WebGL — «MEDIA, большая», внутрь не видим (в v2 пиксельная ретина это закроет).
- Shadow DOM: DOMSnapshot его отдаёт — обрабатываем как обычные ноды.
- Скролл: эскиз = вьюпорт + однострочная сводка про «ниже». Прокрутка = действие мозга, не Глаза.

## v2 — пиксельная ретина (после доказанной петли)
Python-сайдкар (FastAPI): кадр экрана → OmniParser/SAM/PaddleOCR → **тот же PaintNode[]**
(type/box/textLen/clickable-эвристика). Compressor и всё выше — без изменений.
Обучения нет — только инференс готовых моделей.

## Критерии успеха v1
1. Эскиз 5 разных живых страниц ≤30 регионов / ≤600 токенов, глазами — ничего важного не потеряно.
2. Модель решает реальную задачу («найди и включи видео») ТОЛЬКО по glance/focus, без скриншотов.
3. Токены на задачу ≤⅓ от скриншотного подхода.
4. watch() на живой странице: события осмысленны, спама нет.
