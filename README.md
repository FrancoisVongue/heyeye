# heyeye — глаза и руки агента на Linux (X11)

Агент получает не картинку экрана, а короткое текстовое описание: что где лежит, где текст и что в нём
написано, у каждого элемента — номер. Действует он тоже по номерам («кликни 12», «напечатай в 7»),
а программа сама переводит номер в пиксели и нажатия.

Работает на X11 («графическая система Linux»). Удобнее всего на виртуальном экране Xvfb
(«X-сервер без монитора, рисует экран в памяти»): у агента свой экран, своя мышь и клавиатура,
твой рабочий стол он не трогает, разрешений не нужно, экранов можно запустить сколько угодно.

## Как устроено

```
 агент ── HTTP ──▶ src/server.js ──▶ src/perceive.js   разбор кадра по пикселям (картинки, контейнеры,
                        │                 │              кнопки, бары, иконки, текст)
                        │                 └──▶ src/ocr.js  чтение текста PaddleOCR + память прочитанного
                        ▼
                  src/x11.js ── stdin/stdout + файл в /dev/shm ──▶ native/x11eye  (C)
                                                                    ├ кадр: общая память X (MIT-SHM)
                                                                    ├ ввод: XTEST
                                                                    └ изменения: DAMAGE + сравнение с копией экрана
```

- **Кадр** снимается через общую память X-сервера и кладётся в файл в оперативной памяти: весь экран
  1280×800 — 3–6 мс, отдельная область — около 0,5 мс. Без PNG и без файлов на диске.
- **Ввод** через XTEST неотличим от настоящего. Текст печатается независимо от раскладки: символ,
  которого нет на клавиатуре (кириллица при английской раскладке), временно назначается на свободную клавишу.
- **Что изменилось.** X-сервер сам сообщает, какие прямоугольники перерисовали (расширение DAMAGE).
  Программы перерисовывают щедро, поэтому помощник хранит копию экрана, сравнивает перерисованные места
  с ней по клеткам 8×8 и отдаёт точные границы реально изменившихся пикселей. После каждого действия сервер
  ждёт, пока экран успокоится, и отвечает, что поменялось и какие элементы это задело.
- **Память прочитанного.** Текст на экране нарисован системой: одна и та же строка — одни и те же пиксели.
  У каждого найденного куска текста считается отпечаток его пикселей; модель читает только куски с новым
  отпечатком (каждый — на чистом фоне своего цвета, чтобы соседи не влияли). Результат совпадает с чтением
  с нуля, а после прокрутки или ввода почти всё берётся из памяти.

## Запуск

```sh
sudo apt install xvfb libx11-dev libxext-dev libxtst-dev libxdamage-dev   # Debian/Ubuntu
ONNXRUNTIME_NODE_INSTALL=skip npm install    # без скачивания GPU-сборки onnxruntime
npm run build                                # собрать native/x11eye (src/x11.js пересоберёт и сам, если .c новее)

sh scripts/display.sh                        # экран :99 1280×800 + браузер с песочницей
DISPLAY=:99 npm start                        # сервер на http://127.0.0.1:9223
DISPLAY=:99 node test/x11-loop.mjs           # сквозная проверка: разбор, действия, изменения, чтение
```

Другой экран и размер: `EYE_DISPLAY=:100 EYE_SIZE=1920x1080 sh scripts/display.sh https://example.com`.
Модели чтения текста при первом запуске скачиваются сами (если основной источник недоступен — с зеркала на GitHub).

## Запросы

| запрос | что делает |
|---|---|
| `/look?fast=1&depth=N&png=1` | разобрать экран → дерево элементов с номерами; `fast=1` — без чтения текста (только где он); `png=1` — разметка в `shots/look.png` |
| `/read?id=N` или `?box=x,y,w,h` | прочитать текст элемента или области |
| `/detail?id=N&scale=2` | разобрать элемент вблизи (с увеличением) — мелкие части получают новые номера |
| `/act?action=…` | `move` `click` `dblclick` `rightclick` `middleclick` `drag` `pan` `scroll` `type` `key` `hotkey`; точка: `id=` / `box=` / `x=&y=`; цель перетаскивания: `toid=` / `tobox=` / `tox=&toy=`; `scroll`: `dy=` в щелчках колеса; `hotkey`: `keys=ctrl+shift+t`; `drag&hold=shift` |
| `/select?id=N&q=фраза` | выделить фразу мышью по координатам из чтения текста |
| `/changes` | что изменилось с последнего `/look` или `/act` |
| `/wins` | окна: заголовок, положение, размер |
| `/shot`, `/raw?id=N` | сохранить экран или элемент в PNG (для человека) |

Ответ на действие выглядит так:

```
ok: drag @141,237→522,278 · изменилось 3 мест (6% экрана): @949,83 211×28 @80,176 120×120 @420,176 206×206
ok: move @700,700 · на экране ничего не изменилось (ждал 402 мс)
```

## Скорость (2-ядерная облачная машина, экран 1280×800, песочница с журналом событий)

| что | время |
|---|---|
| кадр всего экрана / области 300×200 | 3–6 мс / 0,5 мс |
| движение мыши, клик | 0,2 мс |
| разбор без текста | ~130 мс |
| поиск, где текст | ~300 мс |
| полный разбор, первый взгляд (всё читается) | 2–3,5 с |
| полный разбор после прокрутки или ввода (память) | 0,8–1 с |
| разбор того же экрана повторно | ~0,5 с |

Главное, что осталось медленным, — поиск текста по всему кадру и своя логика разбора на JS.
Следующие шаги — в `ROADMAP.md`.
